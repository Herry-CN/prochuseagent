# 覆盖测算与方案架构

> 受众：仅内部。客户方案书只引用结论，不引用全部公式。
> 上游：URS + 现场勘查
> 下游：BOM 台数、RFQ 续航/回充要求、报价分档

## 1. 覆盖测算

先填场地，再得出“几台狗、几个舱”。不要先选型号。

| 参数 | 符号 | 数值 | 来源 |
| --- | --- | --- | --- |
| 巡检路线长度 | L | __ km | 勘查 |
| 巡检速度（含停顿） | v | __ km/h | 供应商实测，勿用宣传值 |
| 要求重访间隔 | T | __ h | URS Must |
| 单次充电续航 | t_run | __ h | 供应商 |
| 单次充电时长 | t_chg | __ h | 供应商 |
| 每日需要值守时长 | H | __ h | 客户班次 |
| 备用系数 | k | 1.2–1.5 | 故障与雨季 |

**单圈耗时** `t_lap = L / v`

**同时在线巡检台数** `N_online = ceil(t_lap / T)`

**因充电导致的在线率** `eta = t_run / (t_run + t_chg)`

**配置台数** `N = ceil(N_online / eta * k)`

**充电舱数量** 通常 = 台数；若多狗轮流一舱，必须证明时间轴不冲突。

## 2. 系统架构（先系统后品牌）

1. **巡检执行层：** 工业级四足本体 + 云台/热成像/灯光/喊话载荷
2. **补给层：** 自动充电舱、备用电池、避雷与稳压
3. **网络层：** 4G/5G 主链路；必要时本地存储；值班室路由器
4. **值守层：** 网页/客户端、告警、录像、电子地图
5. **人机协同层：** 保安SOP、夜间值班、处警权责
6. **维护层：** 备件包、远程诊断、本地简单更换培训

## 3. 配置分档

| 档 | 满足哪些URS | 典型构成 | 不承诺 |
| --- | --- | --- | --- |
| 试点档 | 核心Must可演示 | 1狗1舱+基础云台+值守软件 | 全场覆盖 |
| 标准档 | 全部Must + 部分Should | 测算台数+热成像+自动回充 | 与复杂VMS深度对接 |
| 旗舰档 | Must + Should + 部分Could | 加平台对接、更多备件、3年SLA | 完全无人值守抓捕 |

超预算时：降档、减Should、缩路线。不擅自删除Must。
